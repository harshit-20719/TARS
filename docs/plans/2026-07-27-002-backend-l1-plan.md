# Backend plan — L1 Conviction (persistence, auth, extraction)

Date: 2026-07-27 · Supersedes units U3–U8 of `2026-07-24-001-feat-capture-scorecard-skeleton-plan.md`
for the deployed reality. The product contract in the spec is unchanged.

## Why this plan replaces the old units

The original plan assumed a **local single-operator tool on SQLite with no login**. Two things changed:

1. **It is deployed to Vercel.** Serverless filesystems are ephemeral — SQLite writes do not
   persist. Real persistence means **Postgres**.
2. **Access decision reversed (D8).** The pilot now wants **real accounts with PM/partner roles**,
   not a no-login single operator. That adds a `User` model, role guards on every write, and
   author attribution on the record.

Everything else holds: the machine drafts, the PM authors, the app renders. No total, no verdict.

## The seam

The front end is **locked**. It reads the record through three getters and nothing else:

```
app/ (locked)  →  listDeals() / getDeal(id) / getRecord(id)  →  Prisma  →  Postgres
```

Today those getters live in `mock/data.ts` and are synchronous. The backend attaches by moving
them to `lib/data.ts` as **async** functions reading the database. This requires adding
`async`/`await` to the 8 page files — signatures and call sites only, no markup, styling, or
component changes. That is the single approved exception to the front-end lock.

`mock/data.ts` survives as the **seed fixture source**, so dev and preview environments look
exactly like today.

## Authorization rules (from spec §4.4, R5)

> **Superseded on authorization.** The table below records what B7 and B8 shipped.
> `docs/plans/2026-07-28-003-feat-l1-completion-plan.md` (U1) revises it: PARTNER
> becomes a full author on the same terms as PM, and the product keeps no read-only
> role. This plan is kept as the record of what was built, not as current intent.

| Action | PM | PARTNER | ADMIN |
|---|---|---|---|
| Read any deal record | ✅ | ✅ | ✅ |
| Create/edit deals, add calls | ✅ | ❌ | ✅ |
| Run extraction | ✅ | ❌ | ✅ |
| Accept / edit / reject observations | ✅ | ❌ | ✅ |
| Author sub-dimension scores | ✅ | ❌ | ✅ |
| Author 0–10 slides | ✅ | ❌ | ✅ |
| Manage users | ❌ | ❌ | ✅ |

The machine is not a role. It never writes a score or a slide — enforced in the extraction service
by construction (it returns observations and claims only) and asserted by test.

## Implementation units

### B1. Foundations
Dependencies (`prisma`, `@prisma/client`, `@anthropic-ai/sdk`, `zod`, `next-auth`,
`@auth/prisma-adapter`, `bcryptjs`, `vitest`, `tsx`), npm scripts, `.env.example` rewrite,
local Postgres for dev and a separate test database.

### B2. Prisma schema + migration
Models mirroring `mock/types.ts` exactly: `Deal`, `Call`, `Observation`, `Claim`,
`SubDimensionScore`, `ScoreEvidence` (join), `Slide`, `FounderTypeRead`, plus `User` / `Account` /
`Session` / `VerificationToken` for auth. Layer stamps on observations, scores, slides. Compound
uniqueness on `(dealId, subDimensionKey, layer)` and `(dealId, slideKey, layer)`. DB-level CHECK
constraints for score-value/type agreement and the 0–10 slide range.

**Verification:** `prisma validate` passes; migration applies to an empty database.

### B3. Value codec + domain rules
`lib/domain/codec.ts` — `ScoreValue` (`1..5 | "NE" | "pass" | "unv" | "fail"`) ↔ the DB's
`(scoreType, value)` pair, and Prisma enum ↔ record-type string unions for the two hyphenated
enums. `lib/domain/rules.ts` — the invariants as pure, unit-tested functions:

- a score's value must match its sub-dimension's declared type
- a banked slide may not exceed the L1 cap; a provisional may, and must be ≥ the banked value
- a slide requires a non-empty single-line ceiling guard
- a binary `fail` on a floor row is a floor breach (recorded as fact, never a verdict)
- every write is layer-stamped

**Verification:** unit tests cover each rule's accept and reject case.

### B4. Repository
`lib/db.ts` (Prisma singleton surviving hot reload and serverless reuse) and `lib/repo/*.ts`
returning **exactly** the existing record interfaces — no Prisma types leak past this boundary.
Dates are `DateTime` in the database and formatted to the record's display strings here.

**Verification:** round-trip tests against real Postgres for every entity.

### B5. Seed
`prisma/seed.ts` loads the three fixture deals from `mock/data.ts` plus seed users, idempotently.

**Verification:** seeding twice leaves one copy; `getRecord("halten")` matches the mock byte-for-byte.

### B6. Seam swap
`lib/data.ts` async getters; update the 8 app imports and add `async`/`await`.

**Verification:** `next build` clean; every route renders against the database.

### B7. Auth + roles
Auth.js v5, Google SSO restricted to the `biome.in` domain, plus a dev-only credentials provider
so local development and tests need no OAuth secrets. JWT sessions carrying `id` and `role`.
`requireRole()` guard, and middleware protecting every route.

**Verification:** unauthenticated request redirects; a `PARTNER` write is rejected.

### B8. Mutations
Server actions in `lib/actions/`, each Zod-validated, role-guarded, rule-checked, and
`revalidatePath`-ing: deals, calls, observation decisions, scores with evidence, slides, and the
founder-type read.

**Verification:** each action's happy path, validation failure, and authorization failure.

### B9. Extraction service
`lib/extraction/` — a Zod schema for the model's output, a prompt built from `framework/rubrics.ts`
so the model can only map to real sub-dimension keys, and `client.messages.parse()` with
`zodOutputFormat`. The Anthropic client is injected so tests run without an API key. Two guards
worth naming:

- **Verbatim check.** Every drafted quote must actually appear in the transcript. A quote that
  does not is dropped, not persisted — this is what keeps R3's "verbatim" honest against a model
  that paraphrases.
- **Zero scores.** The service writes `Observation` (draft) and `Claim` (claimed) rows only.

Thinking stays enabled at `effort: "medium"`; refusals are surfaced as a typed error rather than
being read as content.

**Verification:** stubbed-client tests assert observations persist as drafts, claims as claimed,
paraphrased quotes are dropped, and **zero score rows exist** afterwards.

### B10. Tests + ops
Vitest suite over rules, codec, repository, actions, and extraction. README backend section and a
provisioning runbook for Vercel Postgres, the environment variables, and Google OAuth.

## What this plan does not do

- No gate verdict (D1 still open with Srini) — the roll-up renders facts only.
- No within-L1 score history (D11).
- No L2/L3 logic. The layer stamp is the seam those attach to.
- No UI for authoring scores or slides. The mutations exist and are tested; wiring them to
  controls is a separate, explicitly scoped front-end pass.
